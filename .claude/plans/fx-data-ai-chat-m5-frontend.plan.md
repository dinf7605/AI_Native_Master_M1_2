# Plan: 바닐라 프론트엔드 (필수 화면)

**Source PRD**: `.claude/prds/fx-data-ai-chat.prd.md`
**Selected Milestone**: #5 바닐라 프론트엔드 (필수 화면)
**Complexity**: Medium

## Summary
프레임워크 없이 HTML/CSS/JavaScript(ES 모듈)로 한 페이지 앱을 만든다. 필수 화면 네 가지를 한 흐름으로 제공한다.
- 채팅 (메시지 입력, 대화 표시, 로딩 표시)
- 데이터 관리 (추가, 목록, 수정, 삭제)
- 대화 기록 (목록, 불러오기, 삭제)
- 현재 데이터 요약

Render 무료 플랜의 콜드스타트에 대비해 "서버 깨우는 중" 안내를 넣는다.

## Decisions
| 질문 | 결정 | 근거 |
|---|---|---|
| 구조 | `frontend/index.html` + `css/styles.css` + `js/config.js`(API 주소) + `js/api.js`(fetch 래퍼) + `js/format.js`(순수 함수) + `js/app.js`(화면 로직) | 과제 제약(바닐라). 역할별 파일 분리로 읽기 쉬움 |
| 화면 배치 | 상단: 요약 카드 줄(항상 보임). 왼쪽: 대화 목록과 "새 대화". 가운데: 탭 [채팅 | 데이터 관리] | 제출 스크린샷 "요약이 보이는 채팅 화면"을 한 화면에 담을 수 있음 |
| API 주소 | `js/config.js`의 `API_BASE_URL`. 로컬 기본값은 `http://127.0.0.1:8000`. 배포(마일스톤 7)에서는 Vercel 빌드가 환경 변수 `API_BASE_URL`로 이 파일을 다시 생성 | 정적 사이트는 런타임 환경 변수가 없으므로 빌드 시 주입 |
| 로컬 실행 | `python -m http.server 5500 --directory frontend` | 백엔드 CORS 기본값(`localhost:5500`)과 일치. 추가 도구 불필요 |
| 콜드스타트 | 첫 화면에서 `/health`를 호출하고, 3초 넘게 걸리면 "서버를 깨우는 중입니다 (최대 1분)" 배너를 띄운다. 최대 90초 동안 재시도한 뒤 결과를 표시한다 | 과제 요구 "첫 요청 지연 안내 또는 대응" |
| 로딩 표시 | 질문을 보내면 내 메시지를 즉시 표시하고, "답변을 작성하고 있어요…" 말풍선(점 애니메이션)을 띄운다. 입력창과 버튼은 비활성화한다 | 과제 필수 "로딩 표시" |
| 이어 쓰기 | 현재 대화 ID를 들고 있다가 다음 질문에 `conversation_id`로 보낸다. "새 대화"는 초기화한다. 불러온 대화에서도 이어서 질문할 수 있다 | 마일스톤 4 API와 연동 |
| 데이터 관리 | 폼 하나로 추가와 수정을 겸한다 (목록의 "수정"을 누르면 폼에 채워지고 버튼이 "수정 저장"으로 바뀜). 삭제는 `confirm` 후 실행. 목록은 최신 날짜부터 표시. 변경 후 목록과 요약을 다시 불러온다 | CRUD 3종이 화면에서 보임 |
| 오류 표시 | API의 `detail`을 사람이 읽는 문장으로 바꿔 알림 영역에 표시 (422 배열 포함) | 과제 "최소한의 예외 처리" |
| 보안 | 서버·사용자·AI 텍스트는 모두 `textContent`로만 넣는다 (`innerHTML`에 데이터 금지). 키는 프론트에 두지 않는다 | XSS 방지, 키 관리 |
| 다크 모드·그래프·내보내기 | 이번 범위 밖(마일스톤 6). 다만 색은 CSS 변수로 정의해 둔다 | 범위 분리 |
| 테스트 | `format.js` 순수 함수는 Node 내장 `node --test`로 검증 (의존성 0). 화면은 브라우저 패널에서 실제 백엔드와 E2E로 확인 | 프레임워크 없이 검증 |

## Tasks
1. `format.js` 테스트 먼저 작성 → 구현 (금액 `1,466.60원`, 추세 라벨과 부호, 422 오류 배열, 날짜 정렬)
2. `api.js`: `request()`를 만든다.
   - 기본 URL + JSON을 처리한다.
   - AbortController로 타임아웃을 건다 (기본 15초, 채팅 70초).
   - 네트워크 오류, 비정상 응답은 `ApiError`로 바꾼다.
3. `index.html` + `styles.css`: 레이아웃, 반응형 (좁은 화면에서는 대화 목록을 위로 보냄)
4. `app.js`: 기능별로 구현한다.
   - 서버 깨우기
   - 요약
   - 대화 목록 / 불러오기 / 삭제 / 새 대화
   - 채팅 전송과 로딩
   - 데이터 목록 / 추가 / 수정 / 삭제
5. 브라우저 E2E (실제 백엔드 + 게이트웨이):
   - 첫 로딩, 요약 표시
   - 질문 1회 (로딩 표시 확인)
   - 대화 목록 갱신 → 새 대화 → 이전 대화 불러오기
   - 데이터 추가 → 요약 개수 147 → 수정 → 삭제 → 146
   - 테스트 데이터와 대화 정리

- **채팅**: 추천 질문 클릭 → 답변 표시, 제목이 질문으로 바뀌고 왼쪽 목록에 추가됨
- **로딩 표시** (요청을 3초 지연시켜 확인):
  - "답변을 작성하고 있어요" 말풍선이 뜬다

  - 버튼이 "답변 대기 중…"으로 바뀐다
- **이어 쓰기**: "그럼 최신값은 평균보다 높아 낮아?" → "1,368.60원은 평균 1,466.60원보다 98.00원 낮습니다", 같은 대화에 메시지 4개
- **불러오기**: 새로고침 후 목록에서 대화를 선택하면 메시지 4개가 복원되고 목록에서 강조된다
- **데이터 CRUD**:
  - 추가: 147개, 최신값 갱신, 새 행 강조
  - 같은 날짜 다시 추가: 409 안내
  - 수정: "수정 저장", 1,380.00원
  - 삭제: 146개로 복귀. 요약·추세가 매 단계 즉시 갱신
- **콜드스타트**: 백엔드를 중지하고 새로고침하면 4초 뒤 배너와 "서버 깨우는 중"이 표시된다. 백엔드를 재시작하면 자동으로 "서버 연결됨"이 되고 데이터를 불러온다
