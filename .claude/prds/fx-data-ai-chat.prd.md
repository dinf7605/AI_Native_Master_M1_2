# 환율/주가 데이터 기반 AI 채팅 서비스 (M1-2)

## Problem
환율·주가 같은 시계열 데이터를 가진 사용자는 "최근 추세가 어떤지", "평균 대비 지금 값이 높은지" 같은 질문에 답하려면 원시 데이터를 직접 훑고 계산해야 한다. 범용 GPT 채팅은 사용자가 가진 데이터를 모르기 때문에 이 질문에 근거 있는 답을 줄 수 없다. 이를 해결하지 않으면 데이터는 쌓이기만 하고, 해석은 매번 수작업으로 반복된다.

## Evidence
- 과제 명세(AI응용학습 M1-2)가 요구사항의 1차 근거다. 최종 결과물 4가지, 기능 요구 1~10, 제약사항이 여기에 해당한다.
- 실제 사용자의 불편은 **Assumption — 검증 방법: 프로토타입.** 배포 후 테스트 질문에 대한 AI 답변이 요약 수치를 실제로 반영하는지 확인한다.

## Users
- **Primary**: 특정 환율 또는 종목의 시계열 데이터를 관리하면서, 그 흐름을 자연어로 묻고 싶은 개인. 새 데이터를 추가하거나, 최근 변동을 확인하고 싶을 때 서비스를 연다.
- **Secondary**: 과제 평가자. 배포 URL, Swagger UI, README, 스크린샷으로 기능 동작을 확인한다.
- **Not for**: 실시간 시세나 매매 신호가 필요한 트레이더(투자 조언 제공 안 함), 여러 사용자가 계정별로 데이터를 분리해야 하는 팀 환경.

## Hypothesis
**저장된 시계열 데이터의 요약(기간/개수/기본 통계/최근 추세)을 시스템 프롬프트에 주입하는 AI 채팅**이 **원시 데이터를 직접 분석하지 않고도 데이터 흐름을 자연어로 파악하게** 해줄 것이라고 본다. 대상은 **환율/주가 데이터를 관리하는 개인 사용자**다.
**데이터 관련 테스트 질문 5개 중 5개에서, AI 답변이 `/api/data/summary`의 수치(평균·최대·최소·추세)와 모순 없이 이를 인용할 때** 가설이 맞았다고 판단한다.

## Scope
**MVP**
1. **데이터 기반 AI 채팅**: 자연어 질문을 입력하면 저장된 데이터 요약을 반영한 답변이 돌아오고, 응답을 기다리는 동안 로딩 표시가 보인다. 대화는 자동 저장된다.
2. **데이터 관리 (CRUD)**: `(date, value, memo)` 형태로 추가, 목록, 수정, 삭제를 할 수 있다. 잘못된 입력은 검증 오류로 거부하고, 저장 결과를 화면에서 확인할 수 있다.
3. **데이터 요약 표시**: 기간, 개수, 평균/최대/최소, 최근 추세(증가/감소/유지)를 화면에 보여준다.
4. **대화 기록**: 대화 목록을 조회하고, 특정 대화를 선택하면 전체 메시지를 다시 표시한다. 대화 삭제도 지원한다. 불러오기는 **옵션 (A)** 로 확정: 목록은 메타데이터만 반환하고, 대화 1건을 조회할 때 전체 messages를 반환한다.
5. **배포 + 문서화**: 백엔드는 Render, 프론트는 Vercel에 배포하고 배포 URL에서 Swagger UI에 접근할 수 있어야 한다. README에는 서비스 소개, 기술 스택, 배포 URL 3종, 로컬 실행 방법, 환경 변수 목록, 스크린샷 3종을 담는다.
6. **보너스 — 인사이트·UX 고도화** (포함 확정):
   - 추가 지표 1개 이상 (요약 보강 또는 별도 통계 제공)
   - 추세를 보여주는 그래프 1개
   - 데이터 내보내기 (CSV 또는 JSON 다운로드)
   - 다크 모드 토글

**과제가 정한 인터페이스 계약** (구현 방식이 아니라 요구사항)
- 데이터: `POST/GET /api/data`, `PUT/DELETE /api/data/{id}`, `GET /api/data/summary`
- 대화: `POST/GET /api/conversations`, `GET/DELETE /api/conversations/{id}`
- 채팅: `POST /api/chat` — 요약 조회 → 시스템 프롬프트 주입 → GPT 호출 → conversations 자동 저장
- 저장소 컬렉션: `data`, `conversations`
- 고정 스택: FastAPI, Firestore, GPT API, 바닐라 HTML/CSS/JS, Render, Vercel

**Out of scope**
- 보너스 — Function Calling + MCP/GPT Actions 연동: 이번 범위에서 제외했다. 필수 기능과 UX 보너스를 먼저 완성한다.
- 사용자 인증/계정별 데이터 분리: 과제 요구사항에 없고, 단일 사용자 데모로 충분하다.
- 실시간 시세 자동 수집: 과제는 (date, value, memo) 수동 CRUD와 초기 데이터 적재를 요구한다.
- 투자 조언/매매 추천: 라이선스가 필요한 영역이다. AI 답변은 데이터 서술에 한정한다.
- 스트리밍 응답: 로딩 표시만으로 요구사항을 충족한다.
- 프론트엔드 프레임워크: 과제에서 금지.

## Open Questions
- [x] **정확히 어떤 시계열인가?** → USD/KRW 일별 환율 (ECB 기준, Frankfurter API), 2026-03-02 ~ 2026-09-24, 146개. 마일스톤 1에서 확정.
- [ ] **초기 데이터를 어떻게 적재하나?** CSV(`backend/data/usdkrw.csv`)는 준비됐다. Firestore 적재 경로는 마일스톤 2에서 정한다.
- [x] **"최근 추세"의 정의** → 최근 7포인트 평균을 직전 7포인트 평균과 비교하고, ±0.5% 미만이면 유지. 마일스톤 1에서 확정.
- [ ] **추가 지표는 무엇으로 하나?** 후보: 표준편차/변동성, 이동평균, 최근 N일 변화율, 최대 낙폭.
- [ ] **같은 date의 중복 데이터를 허용하나?** 허용하면 요약과 그래프 결과가 달라진다.
- [ ] **채팅 1회 = 새 대화인가, 기존 대화에 이어 쓰기인가?** 불러온 대화에서 이어 질문할 때 이전 메시지를 GPT에 함께 보낼지도 정해야 한다.
- [ ] **Vercel 환경 변수로 API URL을 주입하는 방식**: 바닐라 정적 사이트는 런타임 환경 변수가 없다. 빌드 시 설정 파일을 생성하는 등 과제 요건을 충족할 방법을 확인해야 한다.
- [ ] **OpenAI 모델과 토큰/요청 상한**: 사용할 모델, max_tokens 값, 개발 중 호출 횟수 제한을 정해야 한다.
